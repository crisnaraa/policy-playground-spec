## Stage Details

### Stage 4 — Application Design (REQUIRED)
**Rationale:** The Policy Playground uses a complex hybrid architecture (Go + Python on ECS Fargate, Amazon Bedrock Agents, SQS, Step Functions, DynamoDB, ElastiCache Redis). Prior requirements analysis and user stories have established the service decomposition outline, but detailed component-level design — API contracts, data flows, agent orchestration patterns, and CDK stack organization — require a dedicated Application Design stage to validate and refine the architecture before unit generation.

**Key design concerns to address:**
- Go ↔ Python service contract (internal ALB HTTP + OpenAPI)
- Bedrock Agents tool definitions for hypothesis structuring and Red Team agent
- Step Functions state machine design for study orchestration
- SQS findings delivery and backpressure handling
- ElastiCache Redis cache key schema and TTL strategy
- CDK stack dependency graph and deployment order

---

### Stage 5 — Units Generation (REQUIRED)
**Rationale:** The system comprises 6 distinct backend service units (session-service, policy-service, findings-service, decision-service, agent-service, study-orchestrator) plus a React/Next.js frontend and CDK infrastructure stacks. Each unit has independent responsibilities, data models, and implementation phases. Units Generation will decompose the application design into independently deliverable units with clear boundaries, enabling parallel development tracks.

**Units expected:**
- `session-service` (Go) — session CRUD, DynamoDB
- `policy-service` (Go) — Git integration, rule parsing
- `findings-service` (Go) — SQS consumer, relevance ranking
- `decision-service` (Go) — immutable decision recording
- `agent-service` (Python) — Bedrock hypothesis structuring + Red Team
- `study-orchestrator` (Python) — Step Functions, Redis cache
- `frontend` (React/Next.js) — SPA on S3 + CloudFront
- `infra-cdk` (TypeScript) — CDK stacks (10 stacks)

---

### Stage 6 — Inception Completed (REQUIRED)
**Rationale:** Final stage that consolidates all inception artifacts, validates completeness, and produces the handoff package for the implementation phase. Ensures all dependencies (external study access, SAML IdP, Bedrock model access, governed dataset) are documented and assigned.
